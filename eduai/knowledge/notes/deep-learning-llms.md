# Deep learning and language models

## Neural networks: neurons, weights and layers
A neural network is built from simple units (neurons). Each neuron multiplies its inputs by weights, adds a bias, and applies an activation function: output = f(w₁x₁ + w₂x₂ + … + b). Neurons are arranged in layers: an input layer, one or more hidden layers, and an output layer. "Deep" learning means many hidden layers. Training adjusts the weights and biases so the network's outputs match the desired outputs. A network with enough neurons can approximate very complicated functions, which is why it can learn from images, audio and text.

## Activation functions: ReLU, sigmoid, tanh and softmax
Activation functions add non-linearity; without them, any number of layers would collapse into a single linear function. ReLU(x) = max(0, x) is the default for hidden layers: cheap and effective. Sigmoid squashes values into (0, 1), useful for a binary probability output. tanh squashes into (−1, 1). Softmax turns a vector of scores into probabilities that sum to 1, used for the output of multi-class classifiers and for choosing the next token in language models. Sigmoid and tanh can cause vanishing gradients in deep networks, one reason ReLU became popular.

## Loss functions
A loss function measures how wrong the model's predictions are; training tries to minimise it. Mean squared error (MSE) is standard for regression. Cross-entropy (log loss) is standard for classification: it compares predicted probabilities with the true class and penalises confident mistakes heavily. Binary cross-entropy is for two classes; categorical cross-entropy is for many. Language models are trained with cross-entropy on predicting the next token.

## Gradient descent and the learning rate
Gradient descent minimises the loss step by step. The gradient tells which direction increases the loss fastest, so each step moves the weights a little in the opposite direction: w ← w − η · ∂L/∂w, where η is the learning rate. If the learning rate is too large, training overshoots and diverges or oscillates; if it is too small, training is very slow. Stochastic gradient descent (SGD) computes each step on a small random batch of examples instead of the whole dataset; one full pass over the data is an epoch. Adam is a popular variant that adapts the step size for each weight.

## Backpropagation
Backpropagation is how a neural network computes the gradient of the loss with respect to every weight. After a forward pass computes the prediction and the loss, the backward pass applies the chain rule of calculus from the output layer back to the input layer, reusing intermediate results so all gradients are computed efficiently in one sweep. Gradient descent then uses these gradients to update the weights. Libraries such as PyTorch and TensorFlow do backpropagation automatically (autograd).

## Convolutional neural networks (CNNs)
CNNs are designed for grid-like data such as images. A convolutional layer slides small learned filters (for example 3×3) across the image, detecting local patterns such as edges; deeper layers combine them into textures, parts and whole objects. Because the same filter is reused everywhere, CNNs need far fewer weights than fully connected layers and recognise a pattern wherever it appears. Pooling layers shrink the feature maps. A typical image classifier stacks convolution, ReLU and pooling layers, then a few fully connected layers and a softmax output. Small datasets such as MNIST digits are good first projects.

## Recurrent neural networks (RNNs) and LSTMs
RNNs process sequences one step at a time, keeping a hidden state that carries information from earlier steps, which made them the standard for text and time series before transformers. Plain RNNs struggle to remember long-range information because gradients vanish or explode over many steps. LSTMs and GRUs add gates that control what to keep and forget, which helps with longer sequences. Their step-by-step processing can't be parallelised well, a key reason transformers replaced them for language.

## Tokenization
Language models don't read characters or whole words directly; text is first split into tokens, usually subword pieces from a fixed vocabulary (for example via byte-pair encoding). A common word may be one token, while a rare word is split into several pieces ("tokenization" → "token" + "ization"). Each token is mapped to an ID, and then to an embedding vector. Model limits such as context length and output length are measured in tokens, roughly ¾ of an English word each on average.

## Embeddings and semantic similarity
An embedding is a list of numbers (a vector) that represents meaning, learned so that similar items get nearby vectors: "king" and "queen" are close, "king" and "carrot" are far apart. Similarity between two embeddings is often measured with cosine similarity, the cosine of the angle between the vectors: 1 means the same direction, 0 means unrelated (perpendicular), −1 means opposite. Cosine ignores vector length, so normalising vectors to length 1 makes it equal to the dot product. Embeddings power semantic search: find documents whose embeddings are closest to the question's embedding, even if they share no words.

## Transformers and attention
The transformer, introduced in the 2017 paper "Attention Is All You Need", is the architecture behind modern language models. Its key part, self-attention, lets every token look at every other token and decide how much each matters for its own meaning: in "The animal didn't cross the street because it was tired", attention helps link "it" to "animal". Each token produces a query, a key and a value vector; attention weights come from comparing queries with keys (softmax(QKᵀ/√d)), and the output is the weighted mix of values. Multiple attention heads capture different relationships. Because all tokens are processed in parallel, transformers train much faster on modern hardware than RNNs. Positional information is added so that word order isn't lost.

## Large language models and small language models
A large language model (LLM) is a transformer trained on huge amounts of text to predict the next token; after pre-training it is usually fine-tuned to follow instructions and chat. Size is measured in parameters (weights): small language models (SLMs) have roughly 0.5 to 4 billion, while frontier LLMs have hundreds of billions or more. Smaller models run on ordinary laptops (especially when quantized), respond faster, cost less and keep data private on the device, but they know less, reason less reliably and make more mistakes. Both kinds can hallucinate, producing confident but wrong statements, so important outputs should be verified, for example by running code.

## How a language model generates text
A language model generates text one token at a time. It reads the prompt, computes a probability for every token in its vocabulary to come next, picks one, appends it, and repeats until it produces an end token or reaches a length limit. Greedy decoding always picks the most likely token; sampling picks randomly according to the probabilities. Temperature controls randomness: the scores are divided by the temperature before softmax, so a low temperature (such as 0.2) makes output focused and repeatable and a high one (above 1) makes it more varied and error-prone. Top-p (nucleus) sampling limits choices to the most likely tokens whose probabilities add up to p. The context window limits how many tokens (prompt plus answer) the model can consider at once.

## Prompt engineering
Prompt engineering is writing inputs that get better outputs from a language model without changing its weights. Effective techniques: state the task and audience clearly ("Explain recursion to a beginner in 5 sentences"); give the model a role and rules in a system prompt; provide examples of the desired input and output (few-shot prompting); ask for a specific format (a table, a code block); break complex tasks into steps; and supply relevant facts in the prompt instead of relying on the model's memory. Asking a model to reason step by step can improve answers on multi-step problems, at the cost of longer, slower responses.

## Retrieval-augmented generation (RAG)
RAG improves answers by giving the model relevant documents at question time. The system searches a collection of trusted text for passages related to the question (using keyword search such as BM25, or embedding similarity), inserts the best passages into the prompt, and asks the model to answer using them. This reduces hallucinations about facts in those documents, lets the system use private or up-to-date information, and makes it possible to show sources. RAG does not change the model's weights; it is not training. Its quality depends on retrieval: if the right passage isn't found, the model falls back on its own knowledge.

## Fine-tuning and LoRA
Fine-tuning continues training a pre-trained model on a smaller, task-specific dataset, for example instruction-answer pairs written for tutoring, so its behaviour adapts to that task. Full fine-tuning updates every weight and needs a lot of memory. LoRA (low-rank adaptation) freezes the original weights and trains small extra matrices that are added to some layers, so only a tiny fraction of parameters (often well under 1%) are trained, making fine-tuning feasible on a single consumer GPU. QLoRA combines LoRA with a 4-bit quantized base model to save even more memory. Fine-tuning changes how a model behaves; for adding factual knowledge, RAG is often cheaper and easier to keep up to date.

## Quantization
Quantization stores a model's weights with fewer bits, for example 4-bit integers instead of 16-bit floating-point numbers, which makes the model file and memory use about four times smaller and often speeds up CPU inference, usually with only a small loss in quality. Very low precision (3 bits or fewer) degrades answers more noticeably, especially for code and reasoning. The GGUF file format used by llama.cpp stores quantized models with names such as Q4_K_M (a 4-bit scheme) or Q8_0 (8-bit). Quantization is applied after training, so it needs no training data, though the quantized model should be re-tested to check for regressions.
